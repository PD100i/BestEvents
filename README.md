# BestEvents
BestEvents - учебный проект по созданию сервиса регистрации и изменения событий.
## Технологии
* .Net9
* ASP.Net
* Docker
* PostgreSQL
* JWT
* Kafka
* Redis
## Предварительные требования
* [.NET SDK 9.0](https://dotnet.microsoft.com/download)
* Visual Studio 2022 / VS Code
* Docker
## Установка и запуск
1. Клонируйте репозиторий
2. Сгенерируйте ключ для Jwt аутентификации, например командой openssl rand -base64 32
3. Переименуйте файл BestEvents\Src\.env.example в .env
4. Откройте файл и замените ключ на сгенерированный ранее
5. В том же файле при необходимости установите пароль для Redis
6. Запустите docker и в терминале выполните команду docker compose up -d 
7. В браузере откройте "http://localhost:5001/swagger" для доступа к сервису Users
8. Выполните регистрацию пользователя, получите Jwt токен по логину и паролю.
9. В браузере откройте "http://localhost:5002/swagger" для доступа к сервису Events. На странице Swagger нажмите кнопку Authorize и введите в поле Value полученное значение токена
10. В браузере откройте "http://localhost:5003/swagger" для доступа к сервису Bookings. На странице Swagger нажмите кнопку Authorize и введите в поле Value полученное значение токена

## Тесты
Для запуска тестов перейдите в папку BestEvents\Src и выполните команду dotnet test bestevents.sln

## Бизнес-логика
Сервис предназначен для регистрации, редактирования и бронирования событий.
Сервис разделен на три микросервиса: Users, Events и Bookings, сязанные через Kafka. Каждый микросервис имеет свою базу данных PostgreSQL.
Архитектурно каждый микросервис разделен на четыре слоя:
* Domain - содержит сущности
* Application - содержит сервисы
* Infrastructure - содержит репозитории
* Presentation - содержит API

## Сервис Users 
Отвечает за регистрацию пользователя и выдачу JWT токена. Доступны две роли пользователя Admin и User.

Эндпоинты:
POST /auth/register регистрирует нового пользователя
POST /auth/login идентифицирует пользователя и возвращает JWT токен

DTO:

Форма регистрации пользователя
Содержит параметры:
 - userName (string) имя(логин) пользователя
 - password (string) пароль
 - role (string) роль пользователя (User/Admin). Необязательный параметр. При отсутствии пользователю назначается роль User

Форма авторизации пользователя
Содержит параметры:
 - userName (string) имя(логин) пользователя
 - password (string) пароль

База данных 

Схема базы данных содержит таблицу users с информацией о пользователе. Таблица хранит пароль в виде хэша.  
Для создания миграции перейдите в BestEvents\Src\Users и выполните в терминале команду ef migrations add SomeMigration --project Users.Infrastructure --startup-project Users.Presentation

## Сервис Events 

Отвечает за создание, просмотр и управление событиями

Эндпоинты:

POST /events создает новое событие. При вызове id и availableSeats не передаются. У нового события Id генерируется сервисом, а availableSeats устанавливается равным totalSeats. Доступен только для пользователя Admin

GET /events - возвращает события, фильтруя их по параметрам name, from, to и выполняя пагинацию по page и pageSIze.
Все параметры необязательны. По умолчанию используется пагинация page = 1 и pageSize = 10
Пример строки запроса:'https://localhost:7046/events?title=title&from=2026-01-01&to=2026-02-01&page=1&pageSize=10'
Доступен даже без регистрации

GET /events/top - возвращает топ 10 популярных событий. Доступен даже без регистрации  
В сервисе реализовано кэширование без инвалидации, только по TTL. Так как данные списка некритичны для бизнеса, TTL выбрано 60 с

GET /events/{id} - возвращает событие по идентификатору. Доступен даже без регистрации  
В сервисе реализовано кэширование с инвалидацией. Параметры события меняются часто - каждый раз при бронировании мест. Но так как кэш инвалидируется при каждом изменении, TTL выбрано также 60 с.

PUT /events/{id} перезаписывает существующее событие по идентификатору. Доступен только для пользователя Admin

DELETE /events/{id} удаляет событие по идентификатору. Доступен только для пользователя Admin

DTO:
Событие   
Содержит параметры:  
 - id (String / GUID) идентификатор события
 - title (String) название мероприятия.
 - description (String) детальное описание или дополнительная информация.
 - startAt (String / Date) дата начала. Формат: YYYY-MM-DD (ISO 8601).
 - endAt (String / Date) дата окончания. Формат: YYYY-MM-DD (ISO 8601).
 - totalSeats (Integer) общее количество мест.
 - availableSeats (Integer) доступное количество доступных мест.

База данных:    
Содержит таблицы events, inbox и outbox.  
Inbox и outbox общие для всех сообщений  
Для создания миграции перейдите в BestEvents\Src\Users и выполните в терминале команду ef migrations add SomeMigration --project Events.Infrastructure --startup-project Events.Presentation

## Сервис Bookings 

Отвечает за создание, просмотр и управление бронированиями

Эндпоинты:

POST /booking/{id}/book создает новое бронирование на событие с идентификатором id, присваивает ему статус Pending и пубикует событие о создании бронирования в брокер сообщений Для последующей обработки сервисом Events. Возвращает URL эндпоинта для проверки статуса события /booking/{id}.  

GET /booking/{id} возвращает информацию о бронировании по его идентификатору. Доступен только для авторизованного пользователя, создавшего бронирование

DELETE /booking/{id} переводит меняет статус бронирования на Cancelled. Доступно только для пользователя, создавшего бронирование и пользователя с ролью Admin

DTO:
Бронирование 
Содержит параметры:
 - id (String / GUID) идентификатор бронирования
 - eventId (String / GUID) идентификатор события
 - userId (String / GUID) идентификатор пользователя
 - status (String) статус бронирования (pending - в ожидании, confirmed - подтверждена, rejected - отклонена, cancelled - отменена)
 - createdAt (String / Date) дата начала. Формат: YYYY-MM-DD (ISO 8601).
 - processedAt (String / Date) дата окончания. Формат: YYYY-MM-DD (ISO 8601).

База данных:
Содержит таблицы events и outbox.
Outbox общая для всех сообщений
Для создания миграции перейдите в BestEvents\Src\Users и выполните в терминале команду ef migrations add SomeMigration --project Bookings.Infrastructure --startup-project Bookings.Presentation

## Взаимодействие через брокер сообщений

Создание и подтверждение бронирования:
При запросе POST /booking/{id}/book сервисом bookings создается новое бронирование со статусом Pending. Событие публикуется в топик booking_created. Для защиты от дублирования публикаций реализован паттерн Outbox. Консьюмер на стороне сервиса events читает сообщение. Для защиты от дублирования сообщений реализован паттерн Inbox. Сервис Events проверяет условия бронирования на событие (событие существует, еще не началось, достаточно мест), уменьшает число доступных мест и публикует событие в топик seats_reserved. Если невозможно зарезервировать места, сервис публикует сообщение в топик seats_reservation_error. Для защиты от дублирования публикаций реализован паттерн Outbox. Консьюмеры на стороне сервиса Bookings принимают то или иное сообщение. В первом случае бронирование переводится в статус Confirmed, во втором - Cancelled.

Отмена бронирования:
При запросе DELETE /booking/{id} сервис bookings переводит статус бронирования в Canelled. Для защиты от дублирования публикаций реализован паттерн Outbox. Консьюмер на стороне сервиса events читает сообщение. Для защиты от дублирования сообщений реализован паттерн Inbox. Сервис Events увеличивает число доступных мест. Обратног сообщение не передается.
